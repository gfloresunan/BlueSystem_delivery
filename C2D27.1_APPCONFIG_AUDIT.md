## 1. Schema & Structure Verification

In `flutter_client/lib/core/config/app_config.dart`:
- `enum PlatformType { android, ios, web }`
- `enum EnvironmentType { development, staging, production }`
- `enum AppConfigStatus { draft, active, deprecated, archived }`
- Type aliases provided for cross-version compatibility:
  - `typedef AppPlatform = PlatformType;`
  - `typedef AppEnvironment = EnvironmentType;`
- `AppDistributionConfig`:
  - `appName`, `shortName`, `applicationId`, `bundleId`, `versionName`, `buildNumber`
- `AppProviderConfig`:
  - `firebaseProjectId`, `firebaseAppId`, `mapsApiKey`, `notificationSenderId`, `apnsKeyId`
- `AppConfigEntity`:
  - `configId`, `tenantId`, `brandId`, `platform`, `environment`, `distribution`, `providers`, `featureFlags`, `runtimeThemeOverrides`, `status`, `schemaVersion`, `createdAt`, `updatedAt`
  - Convenience factory: `AppConfigEntity.createDefault(...)`
  - Computed getter: `String get applicationId => distribution.applicationId;`

---

## 2. Invariant: Immutability of Client Identity

- The client application cannot arbitrarily alter its `tenantId` or `brandId` locally.
- App identity is bounded by the active session token claims and verified by server-side rules.
- Local configuration tampering is rejected at the network and Firestore security gate.
