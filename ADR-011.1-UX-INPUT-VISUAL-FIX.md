# Architectural Decision Record — ADR-011.1-UX-INPUT-VISUAL-FIX

## 1. Problem
In the Merchant Onboarding Portal of BlueSystem Delivery, text inputs on the "Datos de Identificación Comercial" (Step 1) and "Ubicación de la Sucursal & Contacto" (Step 2) screens had Lucide icons rendered absolute inside the input area. Due to CSS class application order and specificity, the custom input text left-padding classes (like `pl-10`) were overridden. This caused entered text and placeholders to render directly underneath the icons, creating a severe visual overlap that degraded readability and user experience.

---

## 2. Root Cause
The core css style `.form-input` in [index.css](file:///c:/Users/geral/OneDrive/Escritorio/TECNOCOMP%202026/Sistemas/BlueSystem_delivery/merchant-onboarding-portal/src/index.css) was defined using the CSS shorthand property:
```css
padding: 0.75rem 1rem;
```
Because shorthand properties reset all four side values, this implicitly set `padding-left: 1rem (16px)`. Due to CSS specificity and loading order, this shorthand rule consistently overrode the Tailwind utility classes (such as `pl-10` or `pl-11`) specified on the `<input>` elements. Consequently, the input text started only 16px from the left edge, placing it directly behind the absolute-positioned icons which occupied the same area.

## 4. UX Decision
Following BlueSystem Enterprise design principles, it was decided to **remove decorative icons** from inside all standard data-entry text inputs in Step 1 and Step 2. Text inputs should adopt a clean, distraction-free aesthetic consisting of:
1. **LABEL** (uppercase, high-contrast tracking)
2. **INPUT** (clean, bordered field with consistent starting padding)
3. **HELPER TEXT** (discreet metadata instructions below)

Icons remain active solely in functional elements (e.g. section headers, buttons, navigation steps, and state badges).
For functional inputs (like the search bar in `StatusCheckPage`), the icon is retained but the spacing is secured by fixing the padding override issue.

---

## 5. Implementation
1. **CSS Shorthand Separation:** Modified `.form-input` in [index.css](file:///c:/Users/geral/OneDrive/Escritorio/TECNOCOMP%202026/Sistemas/BlueSystem_delivery/merchant-onboarding-portal/src/index.css) to declare padding using individual properties (`padding-top`, `padding-bottom`, `padding-left`, `padding-right`). This ensures that utility override classes like `pl-11` operate correctly and are not wiped out by shorthand resets.
2. **Decorative Icon Removal (Step 1):** Removed the absolute elements `<Building2 />`, `<FileText />`, and `<Tag />` from inside inputs in [Step1GeneralInfo.tsx](file:///c:/Users/geral/OneDrive/Escritorio/TECNOCOMP%202026/Sistemas/BlueSystem_delivery/merchant-onboarding-portal/src/components/Step1GeneralInfo.tsx). Stripped the `pl-10` utility class and the `<div className="relative">` wrappers.
3. **Decorative Icon Removal (Step 2):** Removed the absolute elements `<User />`, `<Phone />`, and `<Mail />` from inputs in [Step2LocationContact.tsx](file:///c:/Users/geral/OneDrive/Escritorio/TECNOCOMP%202026/Sistemas/BlueSystem_delivery/merchant-onboarding-portal/src/components/Step2LocationContact.tsx). Stripped the wrappers and classes to ensure layout consistency.
4. **Pointer Events & Spacing Resolution (Status Page):** Added `pointer-events-none` to the Search icon in [StatusCheckPage.tsx](file:///c:/Users/geral/OneDrive/Escritorio/TECNOCOMP%202026/Sistemas/BlueSystem_delivery/merchant-onboarding-portal/src/pages/StatusCheckPage.tsx). With the padding override resolved, `pl-11` successfully forces text to start at `2.75rem (44px)` without overlapping the search icon.

## 7. Before/After Behavior
* **Before:** Text entered by the user (e.g. "Chanchito") rendered directly behind the absolute Lucide icons. Placeholders and focus ring indicators suffered from identical overlaps.
* **After:** Form fields display empty, clean input boxes. User typing and system autofill text start exactly 16px (`1rem`) from the left boundary, with zero obstructions. Search bar text starts at 44px (`2.75rem`), with the search icon perfectly positioned and non-interactive.

---

## 8. Responsive Testing
* Tested on simulated viewports:
  * **Desktop (1920x1080) & Laptop (1366x768):** Form inputs align in two-column grid. Clean borders and focus rings remain balanced.
  * **Tablet (768px):** Inputs collapse to single-column blocks gracefully.
  * **Mobile (390x844 & 360x800):** Form adapts nicely with no clipping or layout overflow. Inputs and helper text scale proportionally.

## 9. Accessibility Testing
* Focus ring outlines (`focus-visible` styling) work seamlessly across all inputs.
* TAB navigation correctly steps through inputs sequentially without skipping hidden fields.
* Form labels are explicitly associated with inputs. Removed decorative icon nodes which improves screen reader compliance and eliminates unnecessary ARIA properties.
