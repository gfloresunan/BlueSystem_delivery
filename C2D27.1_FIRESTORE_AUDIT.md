## 1. Canonical Collections Inventory

The Flutter Commercial Client interacts exclusively with established core collections:

| Collection Path | Flutter Service | Role / Description |
| :--- | :--- | :--- |
| `/orders` | `FirestoreOperationsService` | Commerce order lifecycle, items, status & payment metadata. |
| `/deliveryTrips` | `FirestoreOperationsService` | X→Y trip dispatch, courier assignment, live coordinates. |
| `/tenants` | `FirestorePlatformService` | Tenant master records and organization metadata. |
| `/brands` | `FirestorePlatformService` | Multi-brand visual configurations, colors, and typography. |
| `/subscriptions` | `FirestorePlatformService` | Tenant plan tier, quotas, active/suspended status. |
| `/app_configs` | `FirestorePlatformService` | Client distribution, feature flags, provider settings. |
| `/users` | `FirebaseAuthService` | User profile documents and FCM token arrays. |
| `/user_devices` | `PlatformNotificationAdapter` | Multi-device push registrations (`{uid}_flutter`). |
| `/ubicaciones_repartidores` | `FirestoreOperationsService` | High-frequency courier GPS sink. |

## 2. Invariant Compliance: Zero Parallel Schemas

- **Zero Parallel Collections:** No `flutter_orders`, `mobile_trips`, or brand-prefixed collections exist.
- **Strict Tenant Filtering:** All collection queries explicitly filter by `where('tenantId', isEqualTo: activeTenantId)`, adhering to server-side security rules in `firestore.rules`.
- **Zero Client-Side Mass Ingest:** Read budgets are bounded by pagination and limit constraints, compliant with ADR-003.
