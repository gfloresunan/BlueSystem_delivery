## 1. Initialization Architecture

In `flutter_client/lib/main.dart`:
```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  AppLogger.info('Main', 'Initializing BlueSystem Delivery Commercial Flutter Client v2.2 (C2D.26)');

  try {
    await Firebase.initializeApp();
    AppLogger.info('Main', 'Firebase initialized successfully');
  } catch (e) {
    AppLogger.error('Main', 'Firebase initialization failed', e);
  }

  runApp(const BlueSystemDeliveryApp());
}
```

---

## 2. Platform Options Resolution Analysis

1. **Android Execution:**
   - When running on Android, `Firebase.initializeApp()` automatically resolves configuration values directly from `google-services.json` processed by the Google Services Gradle plugin.
   - This ensures 100% parity with Track A native Android.
2. **iOS Execution:**
   - When running on iOS, `Firebase.initializeApp()` automatically resolves configuration values from `GoogleService-Info.plist` located in the Xcode Runner bundle.
3. **Web / Headless / Alternative Platforms:**
   - If Web or desktop execution is authorized in future phases, options can be supplied via `FirebaseOptions` populated from secure runtime configuration (`AppConfigEntity.providers`).

---

## 3. Security & Anti-Leakage Invariants

- **Zero Hardcoded Secrets:** No API keys, database URLs, or project credentials are hardcoded in Dart source code.
- **Platform Separation:** Android credentials are never copied to iOS; each platform consumes its own authentic configuration.
- **Fail-Safe Startup:** In the event that Firebase fails to initialize (e.g. offline boot), the error is caught and logged via `AppLogger.error`, preventing unhandled native crashes.
