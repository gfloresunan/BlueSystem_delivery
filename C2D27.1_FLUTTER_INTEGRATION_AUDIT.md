## 1. Modular Architecture Verification

The Commercial Flutter Client (`flutter_client/`) is organized under clean architectural boundaries:

```
flutter_client/
├── pubspec.yaml                 (Dependencies: Firebase, Geolocator, Google Maps, Secure Storage, Meta, Intl)
├── analysis_options.yaml        (Static analysis rules)
├── lib/
│   ├── main.dart                (Entry point, Firebase initialization, dynamic brand theme, AppShell bootstrap)
│   ├── core/
│   │   ├── auth/                (EIAM v3 roles, memberships, CanonicalCustomClaimsV3)
│   │   ├── brand/               (BrandEntity, BrandVisualConfig, brand context)
│   │   ├── config/              (AppConfigEntity, AppDistributionConfig, AppProviderConfig)
│   │   ├── errors/              (BlueSystemException, ErrorCode, PlatformCapabilityException)
│   │   ├── gatekeeper/          (GatekeeperEngine, AccessDecision, fail-closed policy)
│   │   ├── observability/       (AppLogger: audit, info, warn, error)
│   │   ├── subscription/        (SubscriptionEntity, PlanTier, status)
│   │   └── tenant/              (TenantEntity, multi-tenant context)
│   ├── data/
│   │   └── services/            (FirebaseAuthService, FirestoreOperationsService, FirestorePlatformService, MerchantFirestoreService, CloudFunctionsService)
│   ├── domain/
│   │   ├── entities/            (OrderEntity, TripEntity, CatalogEntity, CourierLocationEntity, UserProfileEntity)
│   │   └── services/            (IAuthService, ILocationService, INotificationService, IOrderService, ITripService, IFleetService, IMerchantService)
│   ├── platform/
│   │   ├── gps/                 (PlatformGpsAdapter)
│   │   ├── maps/                (MapPlatformAdapter, SentinelMapAdapter)
│   │   ├── notifications/       (PlatformNotificationAdapter)
│   │   └── storage/             (PlatformSecureStorage)
│   └── presentation/
│       ├── providers/           (SessionState)
│       ├── screens/shell/       (AppShell, tab routing)
│       └── theme/               (BrandThemeBuilder)
└── test/                        (brand_hydration, c2d26_commercial_client, c2d27_integration, gatekeeper)
```

## 2. Invariant Compliance Checklist

| Rule / Invariant | Evaluation Criteria | Observed State | Status |
| :--- | :--- | :--- | :--- |
| **ONE FLUTTER CODEBASE** | Single unified Dart project for all brands & tenants | Single codebase in `flutter_client/` | 🟢 COMPLIANT |
| **ZERO BUSINESS LOGIC DUPLICATION** | Pricing, order validation, trip lifecycle in backend | Delegated to Cloud Functions & Firestore | 🟢 COMPLIANT |
| **ZERO PARALLEL FIRESTORE SCHEMAS** | Uses canonical collections (`/orders`, `/deliveryTrips`) | Strictly canonical schemas consumed | 🟢 COMPLIANT |
| **ZERO TENANT-SPECIFIC BUSINESS FORKS** | Tenants partitioned by data & claims, not code | Single engine parameterized by `tenantId` | 🟢 COMPLIANT |
| **ZERO BRAND-SPECIFIC BUSINESS FORKS** | Brands themed by data & visual config, not code | `BrandThemeBuilder` dynamically hydrates | 🟢 COMPLIANT |
| **ZERO ANDROID-ONLY DOMAIN LOGIC** | Domain entities agnostic of Android SDK | Pure Dart models, no Android imports | 🟢 COMPLIANT |
| **ZERO IOS-ONLY DOMAIN LOGIC** | Domain entities agnostic of iOS SDK | Pure Dart models, no iOS imports | 🟢 COMPLIANT |
